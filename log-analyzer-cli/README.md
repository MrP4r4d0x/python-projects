# 📊 Log Analyzer CLI

Консольная утилита на Python для детального анализа серверных логов.  
Поддерживает форматы **Nginx**, **Syslog (sshd)**, **JSON-логи приложений** и **Slow Query логи СУБД**.  
Позволяет получить глубокую статистику по каждому IP: от запрашиваемых URL и HTTP‑методов до типов ошибок аутентификации и длительности SQL-запросов.

## 📋 О проекте

Инструмент помогает быстро разобраться в том, кто и как взаимодействует с сервером.  
Вместо поверхностного подсчёта частот - группировка по хостам с показом контекста: коды ответов, даты, пользователи, порты, числовые метрики и шаблоны запросов.  
Проект активно развивается: уже реализованы парсеры для всех четырёх форматов, добавлена гибкая обработка дат, возможность агрегации по времени, сбор ошибок парсинга.

## ⚙️ Особенности реализации

*   Объектно‑ориентированный подход - для каждого формата логов написан отдельный парсер.
*   Унифицированное хранилище статистики - класс `IpStats` (категориальные счётчики, числовые списки, ошибки).
*   Парсинг регулярными выражениями с именованными группами и гибкой обработкой необязательных полей.
*   Преобразование дат в единый формат с настраиваемой детализацией (год, месяц, день, час, минута, секунда).
*   Сбор ошибок парсинга: пропущенные поля, неверные форматы дат, некорректные числовые значения.
*   Поддержка числовых метрик (например, `duration_ms`, `query_time`, `rows_sent`) с расчётом среднего, минимума и максимума.
*   Возможность указать глубину вывода (`--top`), тип обрабатываемого файла (`--type`) и уровень агрегации времени (`--time`).
*   Минимальные зависимости - только стандартная библиотека Python.

## 📌 Используемые технологии и концепции

*   **Типы данных:** `str`, `dict`, `list`, `Counter`, `defaultdict`.
*   **Конструкции:** классы, методы, наследование (для расширения), условия, циклы.
*   **Модули:**
    *   `argparse` - гибкая обработка аргументов командной строки.
    *   `pathlib.Path` - проверка существования файла.
    *   `re` - регулярные выражения для точного извлечения полей.
    *   `collections` (`Counter`, `defaultdict`) - удобный подсчёт и структурирование.
    *   `json` - обработка JSON-логов.
    *   `datetime` - преобразование и форматирование дат.
*   **Работа с файлами:** построчное чтение через контекстный менеджер `with open(...)`.
*   **Структура кода:** отдельные классы парсеров, вспомогательные функции и единая точка входа.

## 🚀 Как запустить

### Требования
*   Python 3.8 или выше (используются аннотации типов, `match`‑конструкция в `processing_date`).

### Запуск программы
1.  Скачайте файл `main.py`.
2.  Откройте терминал в папке с файлом.
3.  Выполните команду, указав путь к лог-файлу и его тип:
    ```bash
    python3 main.py -f nginx_sample.log -t nginx --top 5
    ```
    или
    
    ```bash
    python3 main.py -f syslog_sample.log -t syslog --top 10 --time H
    ```

### Параметры
*   -f, --file - (обязательный) путь к файлу логов.
*   -t, --type - (обязательный) тип логов: nginx, syslog, json, db.
*   --top - число строк в каждом топе (по умолчанию 10).
*   --time - уровень агрегации даты/времени (по умолчанию H - час). 
    Допустимые значения:
       *   Y - год
       *   m - месяц (ГГГГ-ММ)
       *   d - день (ГГГГ-ММ-ДД)
       *   H - час (ГГГГ-ММ-ДД ЧЧ)
       *   M - минута (ГГГГ-ММ-ДД ЧЧ:ММ)
       *   S - секунда (ГГГГ-ММ-ДД ЧЧ:ММ:СС)

### Примеры использования:

```bash
# Обработать лог Nginx и показать топ-5 IP, агрегируя даты по дням
python main.py -f nginx_access.log -t nginx --top 5 --time d

# Обработать syslog и показать топ-10 IP, время по часам (по умолчанию)
python main.py -f auth.log -t syslog --top 10

# Обработать JSON-лог с агрегацией по минутам
python main.py -f app.jsonl -t json --time M

# Обработать slow query лог, топ-3 по количеству запросов
python main.py -f mysql-slow.log -t db --top 3
```

### 3. JSON-логи приложений

Каждая строка файла должна быть валидным JSON-объектом с полем ip.

## 📄 Структура кода
*   IpStats - универсальное хранилище статистики для каждого IP.

    *   categorical - defaultdict(Counter) для категориальных данных (URL, методы, коды и т.д.)

    *   numeric - defaultdict(list) для числовых метрик

    *   errors - defaultdict(list) для сбора ошибок парсинга

    *   total_requests - общее количество записей

*   **Классы парсеров:**

    *   NginxParser - парсит access-логи Nginx.

    *   SyslogParser - обрабатывает четыре вида записей sshd.

    *   JsonAppParser - разбирает JSON-логи, выполняет flatten вложенных полей.

    *   DatabaseSlowQueryParser - анализирует многострочные записи slow query лога.

*   **Вспомогательные функции:**

    *   read_file() - выбирает нужный парсер по типу, читает файл, запускает анализ и вывод.

    *   display() -  универсальный вывод отчёта для любого парсера.

    *   processing_date() - преобразует дату/время в строку нужной детализации.

*   **Точка входа**: main() - настройка argparse, проверка аргументов, запуск read_file.

## 🛠 Обработка ошибок и диагностика

Каждый парсер собирает ошибки в контейнер errors внутри IpStats. Типичные ошибки:

*   date_parse_failed - не удалось разобрать дату (неверный формат, отсутствие).
*   <field>_parse_failed - отсутствует или пустое значение поля (например, url_parse_failed).
*   ValueError - невозможность преобразовать строку в число для числовой метрики

В выводе для каждого IP (если ошибки присутствуют) печатается блок [!] Ошибки найденные при обработке, где показывается тип ошибки, количество и до трёх примеров проблемных значений. Это помогает быстро оценить качество парсинга и выявить нестандартные строки.
