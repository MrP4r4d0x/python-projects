# 📊 Log Analyzer CLI

Консольная утилита на Python для детального анализа серверных логов.  
Поддерживает форматы **Nginx (access.log)** и **Syslog (sshd)** и позволяет получить глубокую статистику по каждому IP: от запрашиваемых URL и HTTP‑методов до типов ошибок аутентификации.

## 📋 О проекте

Инструмент помогает быстро разобраться в том, кто и как взаимодействует с сервером.  
Вместо поверхностного подсчёта частот – группировка по хостам с показом контекста: коды ответов, даты, пользователи и порты.  
Проект развивается: в ближайших версиях появятся парсеры для JSON‑логов приложений и медленных запросов БД, а также экспорт отчётов в CSV/HTML.

## ⚙️ Особенности реализации

*   Объектно‑ориентированный подход – для каждого формата логов написан отдельный парсер.
*   Парсинг регулярными выражениями с именованными группами – надёжное извлечение данных даже из нестандартных строк.
*   Иерархическая агрегация с помощью `collections.defaultdict` и `Counter`.
*   Возможность указать глубину вывода (`--top`) и тип обрабатываемого файла (`--type`).
*   Минимальные зависимости – только стандартная библиотека Python.

## 📌 Используемые технологии и концепции

*   **Типы данных:** `str`, `dict`, `list`, `tuple`, `Counter`, `defaultdict`.
*   **Конструкции:** классы, методы, наследование (задел на будущее), условия, циклы.
*   **Модули:**
    *   `argparse` – гибкая обработка аргументов командной строки.
    *   `pathlib.Path` – проверка существования файла.
    *   `re` – регулярные выражения для точного извлечения полей.
    *   `collections` (`Counter`, `defaultdict`) – удобный подсчёт и структурирование.
*   **Работа с файлами:** построчное чтение через контекстный менеджер `with open(...)`.
*   **Структура кода:** отдельные классы парсеров и единая точка входа.

## 🚀 Как запустить

### Требования
*   Python 3.8 или выше (используются фичи `:=` и аннотации типов, при желании можно снизить до 3.6).

### Запуск программы
1.  Скачайте файл `log_analyzer.py`.
2.  Откройте терминал в папке с файлом.
3.  Выполните команду, указав путь к лог-файлу и его тип:
    ```bash
    python3 log_analyzer.py -f nginx_sample.log -t nginx --top 5
    ```
    или
    ```bash
    python3 log_analyzer.py -f syslog_sample.log -t syslog --top 10
    ```

### Параметры
*   -f, --file — (обязательный) путь к файлу логов.
*   -t, --type — (обязательный) тип логов: nginx или syslog.
*   --top — число строк в каждом топе (по умолчанию 10).

## 2. Syslog (sshd)
**Распознаются четыре типа событий:**

*   Failed password – неудачная попытка входа

*   Invalid user – попытка входа под несуществующим пользователем

*   Connection closed by – разрыв соединения

*   authentication failure – детальный отчёт об ошибке аутентификации

**Для каждого события собираются:**

*   дата, PID процесса, имя пользователя, порт (для первых трёх)

*   для authentication failure – дополнительно logname, uid, euid, tty, ruser

## 📄 Структура кода
*   **Классы парсеров:**

    *   NginxParser – парсит строки логов Nginx, хранит статистику в ip_analytics.

    *   SyslogParser – обрабатывает четыре вида записей sshd, группирует по IP и типу ошибки.

    *   JsonAppParser, DatabaseSlowQueryParser – заглушки для будущих форматов.

*   **Вспомогательные функции:**

    *   read_file() – выбирает нужный парсер по типу, читает файл, запускает анализ и вывод.

    *   main() – точка входа, настройка argparse.

*   **Методы классов:**

    *   parser_log(line) – обрабатывает одну строку.

    *   display(top_n) – выводит детализированный отчёт по топ‑N IP.

## 🔮 Планы по развитию
*   **Оптимизация** – кэширование скомпилированных регулярных выражений и снижение накладных расходов при очень больших файлах.

*   **Новые форматы** – поддержка JSON‑логов приложений (jsonApp) и логов медленных запросов (DatabaseSlowQuery).

*   **Экспорт результатов** – сохранение отчётов в CSV, HTML или JSON для дальнейшего анализа.

*   **Интерактивный режим** – фильтрация по IP, временному диапазону и кодам ответа без перезапуска.
